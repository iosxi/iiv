# iiv-client

Windows 10 / 11 用のリモート デスクトップのクライアントです。ほかの PC の画面を見たり操作したりします。
相手は [iiv-server](../server/README.md) です。

[iivnc-client](https://github.com/iosxi/iivnc-client)(VNC のビューア)の後継で、**VNC の規格を捨てて**、
画面を H.264 の動画として受け取り、GPU で復号して描きます。VNC のサーバーにはつながりません。

- **軽い。** 1920×1080 で全面が毎フレーム変わる絵を 60 フレーム/秒で受けて、CPU は 1 フレームあたり 1.9ms(下の「測った結果」)。
- **インストール不要。** `iiv-client.exe` を好きな場所に置いて起動するだけ。H.264 の復号には Windows に最初からある
  Media Foundation を使います(追加のコーデックは要りません)。
- **レジストリを使わない。** 設定・接続先の履歴・覚えたパスワードは exe と同じ場所の `iiv-client.ini` だけ。

入手は [iiv のリリース](https://github.com/iosxi/iiv/releases) から。iiv-server は**同じ版**のものを使ってください。
作り始めたばかりなので、下の「できないこと・確かめていないこと」も読んでください。

## 使い方

1. `iiv-client.exe` を起動し、サーバー(相手の PC のアドレスや名前)とパスワードを入れて「接続」。
   - 書き方: `192.168.1.10`、`pc-name`(ポート 5960)、`host:5961`(ポートを指定)、`[fe80::1]:5961`
   - 「覚える」にすると、次からその接続先を選ぶだけでパスワードが入ります。パスワードは Windows の DPAPI で
     暗号にして ini に置きます(この PC にこの利用者でログインしているときだけ戻せます)。
2. 相手の画面が窓に出ます。窓の大きさに合わせて縮めて表示します(等倍にもできます)。
3. **F8** でメニュー(全画面、窓に合わせる / 等倍、画質、描画、Ctrl+Alt+Del を送る、見るだけ、切断 など)。
   同じものが窓のシステム メニュー(タイトル バーの右クリック)にもあります。
4. **Ctrl+Alt+Enter** で全画面の切り替え。全画面の間は、Windows キーや Alt+Tab も相手へ送ります。
5. 全画面のときに**画面の上端へマウスを当てる**と、帯が出ます(「窓に戻す」「メニュー」「最小化」「切断」)。
   メニューの「速さを表示」がオンなら、帯の右端にフレームレートと帯域(例: `60.0 fps  20.5 Mbps`)も出ます。

コマンド ラインでもつなげます: `iiv-client.exe 192.168.1.10 -fullscreen`

### 画質

画質はサーバーへ「どのくらいの帯域まで使ってよいか」を伝えます。

| 選択肢 | 中身 |
|---|---|
| 自動(おすすめ) | サーバーに任せる。動いている間は軽く、止まったらくっきり(帯域は画面の動きしだい。4K でも数 Mbps〜十数 Mbps) |
| 高め(LAN 向け) | 上限 60Mbps |
| 控えめ(Wi-Fi・遠隔地) | 上限 10Mbps |
| 細い回線 | 上限 3Mbps |

### 描画(GPU / GDI)

- **GPU(既定)** … H.264 を GPU で復号し(DXVA)、絵を CPU に降ろさずにシェーダーで描きます。縮めても文字がきれい。
- **GDI** … CPU で復号して描きます(CPU を多く使います)。GPU が使えない PC 向け。

### 音を鳴らす(v6 から)

接続の画面の「音: **鳴らす**」(または F8 のメニューの「音を鳴らす」)をオンにすると、相手の PC で鳴っている音を
こちらで鳴らします。**iiv-server 側でも「音を鳴らす」をオンにしたときだけ**鳴ります(既定はどちらもオフ。
チェックの状態は ini に残ります)。サーバー側で切られているときは、メニューの項目にそう出ます。

| 音質 | 中身 | 帯域 | 音が取り込まれてから鳴るまで |
|---|---|---|---|
| 音質優先(既定) | そのまま送る(16bit・48kHz・ステレオ。劣化なし) | 1.5Mbps | 約 50〜60ms |
| 速度優先 | AAC 96kbps に縮める(Windows 標準のエンコーダ) | 0.1Mbps | 約 130〜140ms |

- どちらでも映像のフレーム/秒は変わりませんでした(下の「測った結果」)。LAN なら音質優先がおすすめです。
  速度優先は、回線が細いとき(画質「細い回線」など)に、音が映像の帯域を食わないようにするためのものです。
  音は少し劣化し(合成した音で SNR 40〜43dB)、AAC の符号化と復号の分、遅れが 70〜90ms 増えます。
- 鳴らすのは、この PC の既定の再生デバイスです。2 台の PC の時計のずれは、再生の速さを ±0.5% の範囲で
  自動で合わせて吸収します(遅れが溜まったり、途切れたりしないように)。
- 接続中にメニューで切り替えられます。「音を鳴らす」を切ると、サーバーも音の取り込みを止めます。

## 測った結果(2026-10-06。Core i7-12700KF・RTX 3070 Ti・Windows 11。同じ PC の中で iiv-server v1 と)

合成した 1920×1080 の、全面が毎フレーム変わる絵(`tools/pairbench.py`)。

| | GPU で復号 | CPU で復号 | 参考: iivnc-client v10(GPU 描画) |
|---|---|---|---|
| フレーム/秒 | 60 | 60 | 116〜120 |
| 帯域 | 21Mbps | 21Mbps | 800Mbps 前後 |
| CPU(1 フレームあたり) | **1.9ms** | 13.5ms | 13〜14ms |

フレーム/秒は、表示を画面の書き換え(60Hz)に合わせているので 60 で頭打ちになります。

**音を鳴らすとき(v6。2026-10-07、同じ条件で 3 回ずつ。サーバーは合成した音、こちらは音量 0 で鳴らす)。**

| 音 | フレーム/秒 | 帯域 | クライアントの CPU | サーバーの CPU |
|---|---|---|---|---|
| 鳴らさない | 58.3〜58.9 | 18.5Mbps | 11〜15% | 30〜31% |
| 音質優先 | 59.1〜59.3 | 20.2Mbps | 14〜18% | 30〜32% |
| 速度優先 | 59.0〜59.1 | 18.7Mbps | 15〜18% | 31〜33% |

`tools/audiocheck.py` で 60 秒: 音質優先は受け取った音がサーバーの音と 1 サンプルずつ同じで、欠け・途切れ 0。
速度優先は SNR 43dB、欠け・途切れ 0。

## できないこと・確かめていないこと

- **色の付いた細かい文字の縁が少しにじみます**(H.264 は色の情報を 4:2:0 で送るため。明るさはよく合う)。
- 通信は暗号化していません。LAN の中か、VPN の中で使ってください。
- 確かめていないこと: **Windows 10 の機械**、Intel / AMD の GPU、**クリップボードとファイルのコピー＆貼り付け**
  (iivnc-client のものを引き継いだが、iiv では動かしていない)、2 台の実機の間。
- 音を鳴らす: 確かめたのは同じ PC の中で、合成した音を音量 0 で鳴らすところまで。**実際に耳で聞くこと**、
  2 台の PC の間(時計のずれの吸収が実際に働くか)、再生デバイスを途中で切り替えること・抜くことは確かめていません。

## コマンド ライン

| 引数 | 意味 |
|---|---|
| `<サーバー>` | すぐにつなぐ(パスワードは覚えたものか、聞く) |
| `-password <pw>` / `-viewonly` / `-fullscreen` | パスワード / 見るだけ / 全画面で開く |
| `-quality auto\|lan\|wifi\|slow` | 画質 |
| `-render gpu\|gdi`(`-gpu`・`-gdi`) | 描画の方式 |
| `-audio quality\|speed\|off` | 音を鳴らす(音質優先 / 速度優先)/ 鳴らさない |
| `-ini <path>` / `-log` | 別の設定ファイル / ログを書く |
| `-dump <bmp>`、`-exitafter N`、`-idleexit ms`、`-audiodump <wav>`、`-audiomute` | 検証用 |
